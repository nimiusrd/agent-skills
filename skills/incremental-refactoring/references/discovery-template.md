# 候補記録

ファイルとIssueで共通の記録内容を使う。既存形式を尊重し、次の情報を不足分だけ補う。固定の番号・見出しは必須ではない。

```markdown
# <候補ID>: <目的>
- 対象: ファイル・シンボルまたは責務
- 根拠と期待効果:
- 影響範囲:
- 今回の変更範囲と完了条件:
- 検証: 重要な経路ごとの振る舞い・検証方法・確認済み／未確認、実行コマンド・結果
- 状態: 未着手 / 実施中 / 中断 / 完了 / 対象外 / 分割済み
- 現状照合: 日時、コミットと未コミット変更の有無（取得可能な場合）
- 次の着手点・再開条件:
- 関連候補: 親・子・依存先（ある場合）
```

別のセッションでも対象と判断根拠が分かる具体性を保つ。完了時にも検証結果を残す。分割時は親子を相互に参照し、対象外では理由を記録する。無関係な候補は変更・削除しない。

## Issueを使う場合

- 原則、一つの独立した候補を一つのIssueにする。作成前に同じ対象・目的の既存Issueを確認し、存在すれば更新する。タイトルの一致だけで重複と判断しない。既存の根拠・議論・識別子を保持する。
- Issue本文に上記の現在の候補情報を保存する。コメントだけに新しい状態を追記して本文を古いままにせず、検証の詳細や履歴はコメントから参照できる形でもよい。
- 分割時は親と子のIssueを相互リンクし、依存順・今回選ぶ単位・残りの着手条件を明記する。子Issueをまとめて実施する理由にはしない。
- 完了・対象外・中断などの意味は本文に残す。open/closedだけで区別せず、完了や対象外で閉じる場合も理由と検証結果を保存し、履歴を削除しない。閉じた既存Issueを再開する場合も現状を照合する。
- 作成・更新の成功とURLを確認してから保存済みと報告する。書込みできなければ本文案をローカルファイルへ退避し、未登録・未更新であることと再開条件を伝える。応答が不明な場合は既存Issueを照会してから再試行し、重複作成を防ぐ。
