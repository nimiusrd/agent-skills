# PBT の検証観点

設計・実行の結果を確認するための観点。点数やテスト件数を合格条件にしない。

- **仕様性**: 各プロパティが公開された振る舞いに対応し、意味のある誤実装を検出できる。判定根拠が実装から独立している。
- **範囲**: ユーザー指定と比較元を尊重し、現在の変更なら未コミット・未追跡も確認した。対象外とした候補の理由が説明できる。
- **入力**: 前提条件を生成器で表現し、仕様上の境界・異常入力を取りこぼさない。明示例が必要な境界はランダム選択だけに頼らない。
- **縮小とコスト**: 入力は縮小可能で、サイズ・試行回数が処理の計算量に適している。過剰な棄却、タイムアウト、health check の無効化で失敗を隠していない。
- **実行**: 対象テストと必要な型検査・関連テストを実行し、コマンドと結果を記録した。既存の失敗と今回の失敗を区別した。
- **再現と回帰**: 実際の失敗があれば縮小反例とライブラリ固有の再現情報で再実行した。長期保持すべき反例は通常の回帰テストや明示例にできる。

バグ検出力に疑問がある場合、隔離したコピーで代表的な誤実装に置き換え、テストが失敗するか確認するとよい。常に mutation testing 環境を新設する必要はない。
