# 評価ケース

Luna のスキルあり・なしを、同じ課題・実行環境で独立した一時コピーを使って比較する。実行担当には対象promptとfixtureだけを渡し、期待事項や採点用ファイルは渡さない。模擬ケースでは実際のGitHub投稿やGit履歴変更をしない。

実行担当には対象ケースのpromptと入力fixtureだけを渡す。スキルあり側には `evals/` を除外したスキルコピーを追加で渡し、本文中の評価ケース・採点資料へのリンクも除く。両条件とも `evals.json`、期待事項、このREADMEを含む採点資料、他ケース・他条件の結果を参照させない。スキルなし側にはスキル本文も渡さない。採点は実行担当と分離し、実行後の成果物と結果で行う。

## 環境と採点

実行担当へ課題を渡す前に、Python 3.10以上の隔離環境へ対象fixtureの `requirements.txt` を導入する。両条件で同じPython・依存バージョンを使い、各fixtureのコピー内で `python -m unittest discover -s tests -v` により既存テストの成功を確認する。依存を導入できなければ環境ブロックとして記録し、モデルの失敗と混同しない。モデル・reasoning effort・実行コマンド・終了コード・差分と未実施項目を記録し、単発の成否だけでスキルの要否を決めない。

ケース1は、評価担当がHypothesis導入済みのPythonを使い、リポジトリルートから次を実行する。

```sh
python skills/property-test-generator/evals/check_normalization_mutations.py <成果物のfixtureディレクトリ>
```

チェッカーは製品コードと既存テストの保持を確認し、一時コピーで追加された `tests/test_properties_normalizer.py` だけを実行する。正常実装で成功し、定数出力・小文字化・順序逆転・ASCII空白のみの4種の誤実装をすべて検出することを確認する。既存テストだけによる検出は生成テストの検出力に数えない。0件実行、タイムアウト、import等の実行エラーは正常実装の成功や誤実装の検出として認めない。生成テストがHypothesisと公開仕様を実際に使っていることも成果物から確認する。このチェッカーは実行担当に渡さない。

ケース2は意図的な製品不具合を含む。生成テストで初出順違反を発見し、Hypothesisの実際の縮小出力と再実行で同じ失敗を確認できることを評価する。特定の反例文字列・最小長を要求せず、手書き反例だけを縮小成功と扱わない。製品コードの修正や期待値の緩和で成功に変えることは不合格とする。
