# Commit and PR

現在の変更を安全に公開し、レビュー可能な Pull Request を作成する。

## ワークフロー

1. 作業ツリー、差分、現在のブランチ、リモート、リポジトリ固有の指示を確認し、今回含める変更を特定する。
2. デフォルトブランチまたは保護ブランチ上にいる場合は、変更内容に合う作業ブランチを作成する。既存の作業ブランチは、目的が今回の変更と一致する場合にそのまま使う。
3. 今回の変更だけをステージし、ステージ済み差分を確認する。秘密情報、認証情報、意図しない生成物、無関係なユーザー変更は含めない。
4. 変更に応じた検証を行い、結果を記録する。失敗を解消できない場合は、成功したように扱わずユーザーへ伝える。
5. リポジトリの慣例に沿った簡潔なコミットを作成する。
6. ブランチをプッシュし、差分とコミット履歴に基づいて PR を作成する。PR には少なくとも変更の目的、主な変更点、実施した検証を正確に記載する。
7. PR の URL と、レビュー時に知っておくべき検証結果や残課題を返す。

## 制約

- 変更がなければ、空コミットや空の PR を作らない。
- ユーザーの明示的な許可なしに force push、検証フックの回避、公開済みコミットの amend を行わない。
- 対象変更が曖昧で、無関係な変更を巻き込む可能性がある場合は、コミット前に確認する。
- 認証、権限、競合、必須チェックなどで公開を完了できない場合は、既に完了した操作と阻害要因を明確に報告する。
